# Hammerspace

> Hammerspace, Inc. builds the Hammerspace Global Data Platform — a parallel file system and software-defined data platform that unifies unstructured data across on-premises storage, edge sites, AWS, Azure and Google Cloud into a single global namespace. Data is reached over NFS, pNFS v4.2 with Flex Files, SMB, S3 and CSI, while placement, tiering, replication, snapshots and retention are driven by declarative objectives. The 2026 AI Data Platform adds Tier-0 NVMe pooling on GPU servers, an integrated Milvus vector database, and Model Context Protocol services for AI agents.

This file was generated by API Evangelist from public sources. Hammerspace does not publish an llms.txt of its own: every path on hammerspace.com, including /llms.txt, is answered by a bot-protection challenge (HTTP 202).

## What is machine-readable, and what is not

- **No public OpenAPI.** Hammerspace publishes no OpenAPI or Swagger description at any public URL. `/openapi.json`, `/swagger.json` and `/api-docs` were probed on hammerspace.com and supportportal.hammerspace.com; the whole github.com/hammer-space organization was searched. Nothing.
- **No public API reference.** Product documentation ships with the software and through the gated customer support portal.
- **No A2A agent card**, no security.txt, no api-catalog, no status page, no webhook or event surface.
- **The one real machine-readable discovery document** on a Hammerspace host is the OpenID Connect configuration for the customer support portal (Salesforce Experience Cloud) — it describes support-portal login, not the data platform API.
- **The best public description of the API is Hammerspace's own Apache-2.0 source code.** The CSI driver's Go client and the Ansible operations playbooks call the real management endpoints and are the evidence behind everything recorded here.

## APIs

- [Hammerspace Anvil Management API](https://hammerspace.com/resources/): REST management control plane served by each customer's own Anvil metadata server at the base path `/mgmt/v1.2/rest`. Covers shares, files, objectives, storage volumes, object-storage volumes, volume groups, data portals, nodes, sites, snapshots, snapshot retentions, replications, schedules, tasks, licences, Active Directory and IdP configuration, antivirus, backup, NTP, syslog and proxy settings.

## How the API behaves

- Authentication: `POST {anvil}/mgmt/v1.2/rest/login` with form-encoded `username` and `password`, establishing a session cookie. No API keys, no bearer tokens, no OAuth. On 401/403 clients re-login and retry once.
- Async: long-running mutations return **HTTP 202 plus a task**; poll `GET /tasks/{id}` until COMPLETED, FAILED, HALTED, CANCELLED, VALIDATION_FAILED or RESUMED.
- Filtering: an RSQL-like `spec` query parameter, e.g. `?spec=schedule.name=eq=<name>` (URL-encoded).
- Tracing: Hammerspace's own client injects a W3C `traceparent` header on every call.
- No idempotency keys, no documented pagination, no RFC 9457 problem details, no rate-limit headers.
- Authorization is role-based per-object-type CRUD ACLs; Hammerspace documents a least-privilege service account pattern for integrations.

## Client libraries and automation

- [hstk](https://pypi.org/project/hstk/) — the `hs` CLI and Python toolkit, Apache-2.0 (`pip3 install hstk`)
- [csi-plugin](https://github.com/hammer-space/csi-plugin) — Kubernetes CSI driver, Apache-2.0; `pkg/client` is the reference Go client for the management API
- [ansible](https://github.com/hammer-space/ansible) — operations playbooks driving the management API
- [terraform](https://github.com/hammer-space/terraform) — deployment automation examples
- [hammerspace-grafana-dashboards](https://github.com/hammer-space/hammerspace-grafana-dashboards) — dashboards for the built-in Prometheus exporters
- Container images: `hammerspaceinc/csi-plugin`, `hammerspaceinc/mds-registrar`, `hammerspaceinc/director-mgmt`
